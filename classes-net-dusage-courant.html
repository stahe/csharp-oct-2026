    5. Classes .NET d'usage courant

    Nous présentons ici quelques classes de la plate-forme .NET fréquemment utilisées : chaînes de caractères, tableaux, collections, fichiers, expressions régulières. Nous y ajoutons LINQ (Language Integrated Query), que le cours de 2008 laissait de côté alors qu'il était déjà disponible depuis C# 3 : c'est aujourd'hui la façon la plus courante de manipuler des collections en C#. Auparavant, nous montrons comment obtenir des renseignements sur les milliers de classes disponibles. Cette aide est indispensable au développeur C#, même confirmé.

    Les exemples de ce chapitre sont, sauf l'application exemple de la fin, des applications fichier unique exécutées par [dotnet run fichier.cs]. Ils se trouvent dans le dossier [05-classes-dotnet] du code du cours et s'exécutent en culture française (fr-FR).

    5.1. Chercher de l'aide sur les classes .NET

    Le cours de 2008 décrivait longuement, copies d'écran à l'appui, l'aide MSDN installée avec Visual Studio 2008. Cette aide locale n'existe plus : la documentation de .NET est aujourd'hui en ligne, gratuite, et mise à jour à chaque version.

    5.1.1. La documentation en ligne

    Le point d'entrée est le site learn.microsoft.com de Microsoft. On y trouve :

    • la documentation du langage C# : https://learn.microsoft.com/fr-fr/dotnet/csharp/. Elle contient une présentation du langage, des tutoriels, la référence du langage (mots clés, opérateurs, instructions) et une rubrique « Nouveautés » qui décrit chaque version de C# ;
    • la référence de l'API .NET : https://learn.microsoft.com/fr-fr/dotnet/api/. Elle décrit, espace de noms par espace de noms, toutes les classes de .NET : leurs constructeurs, propriétés et méthodes, avec des exemples ;
    • le navigateur d'API, sur la même page : une zone de recherche dans laquelle on tape un nom de classe ou de méthode ([StringBuilder], [Regex.Match]…). Une liste déroulante permet de choisir la version de .NET (ici .NET 10).

    La page d'une classe, par exemple System.String, donne :

    • l'espace de noms de la classe et l'assembly qui la contient ;
    • sa déclaration, sa classe parente et les interfaces qu'elle implémente ;
    • la liste de ses constructeurs, propriétés et méthodes, chacune avec un lien vers une page détaillée qui donne ses différentes surcharges, ses paramètres, la valeur rendue, les exceptions possibles et souvent un exemple ;
    • des remarques sur son utilisation.

    Les pages sont disponibles en français (traduction automatique) et en anglais (texte original, parfois plus précis). On passe de l'une à l'autre en remplaçant [fr-fr] par [en-us] dans l'adresse. Une recherche sur un moteur de recherche avec le nom complet de la classe (« System.Text.StringBuilder ») mène en général directement à la bonne page.

    5.1.2. L'aide de l'éditeur

    L'éditeur de code (Visual Studio, Visual Studio Code avec l'extension C# Dev Kit, Rider) fournit une aide immédiate, sans quitter le code :

    • l'autocomplétion (IntelliSense) : après avoir tapé [uneChaine.], l'éditeur propose la liste des propriétés et méthodes de l'objet, avec un résumé de chacune ;
    • le survol : placer la souris sur un nom de classe, de méthode ou de variable affiche sa déclaration et le résumé de sa documentation ;
    • l'aide sur les paramètres : en tapant la parenthèse ouvrante d'un appel, l'éditeur affiche les différentes surcharges de la méthode et le rôle de chaque paramètre ;
    • atteindre la définition (touche F12) : affiche la déclaration de la classe ou de la méthode. Pour une classe de .NET, l'éditeur affiche les déclarations publiques reconstituées à partir de l'assembly, avec leurs commentaires de documentation ;
    • dans Visual Studio, la touche F1 sur un nom de classe ou de méthode ouvre la page correspondante de la documentation en ligne.

    Ces commentaires de documentation, que l'on voit au survol, sont ceux qui servent à générer la référence en ligne. On peut en écrire de semblables dans son propre code, avec la syntaxe [/// <summary> ... </summary>] placée au-dessus d'une classe ou d'une méthode : l'éditeur les affichera de la même façon.

    5.2. Les chaînes de caractères

    5.2.1. La classe System.String

    Le type [string] de C# est un alias de la classe [System.String]. Elle présente de nombreuses propriétés et méthodes. En voici quelques-unes :

    membre
    rôle
    [public int Length { get; }]
    nombre de caractères de la chaîne
    [public char this[int index] { get; }]
    le caractère n° [index] : [chaine[i]]
    [public bool StartsWith(string value)]
    rend [true] si la chaîne commence par [value]
    [public bool EndsWith(string value)]
    rend [true] si la chaîne se termine par [value]
    [public bool Contains(string value)]
    rend [true] si la chaîne contient [value]
    [public bool Equals(string? value)]
    rend [true] si la chaîne est égale à [value] ; équivalent à [chaine == value]
    [public int IndexOf(string value)]
    première position de [value] dans la chaîne, ou -1. Une autre surcharge commence la recherche à la position [startIndex]
    [public int IndexOf(char value)]
    idem pour le caractère [value]
    [public int LastIndexOf(char value)]
    idem [IndexOf] mais rend la dernière position au lieu de la première
    [public string Insert(int startIndex, string value)]
    insère la chaîne [value] dans la chaîne en position [startIndex]
    [public static string Join(string separator, params string[] value)]
    méthode de classe : concatène les éléments de [value] en les séparant par [separator]
    [public string Replace(char oldChar, char newChar)]
    rend une copie de la chaîne où le caractère [oldChar] a été remplacé par [newChar] ; une surcharge remplace une chaîne par une autre
    [public string[] Split(params char[] separator)]
    la chaîne est vue comme une suite de champs séparés par les caractères de [separator] ; le résultat est le tableau de ces champs
    [public string Substring(int startIndex, int length)]
    sous-chaîne de [length] caractères commençant à la position [startIndex]
    [public string ToLower()], [public string ToUpper()]
    rend la chaîne en minuscules, en majuscules
    [public string Trim()]
    rend la chaîne débarrassée de ses espaces de début et de fin ([TrimStart], [TrimEnd] : d'un seul côté)

    On notera un point important : une chaîne de type [string] est immuable, elle ne peut pas être modifiée après sa création. Lorsqu'une méthode rend une chaîne de caractères, celle-ci est une chaîne différente de la chaîne sur laquelle a été appliquée la méthode. Ainsi [s1.Trim()] rend une chaîne [s2], et [s1] et [s2] sont deux chaînes différentes : [s1] n'a pas changé.

    Une chaîne [c] peut être considérée comme un tableau de caractères en lecture seule :

    • [c[i]] est le caractère n° i de [c] (le premier a le n° 0) ;
    • [c.Length] est le nombre de caractères de [c].

    // Split et Join
string ligne = "un:deux::trois:";
// découpage avec le séparateur ':'
string[] champs = ligne.Split(':');
for (int i = 0; i < champs.Length; i++)
{
    Console.WriteLine($"champs[{i}]=[{champs[i]}]");
}
// l'opération inverse
Console.WriteLine($"join=[{string.Join(":", champs)}]");

// les options de Split : suppression des champs vides
champs = ligne.Split(':', StringSplitOptions.RemoveEmptyEntries);
Console.WriteLine($"RemoveEmptyEntries : {champs.Length} champs [{string.Join("|", champs)}]");

// plusieurs séparateurs et suppression des espaces autour des champs
string personne = " dupont , jean ;  45 ";
champs = personne.Split([',', ';'], StringSplitOptions.TrimEntries);
Console.WriteLine($"TrimEntries : {champs.Length} champs [{string.Join("|", champs)}]");

// les deux options combinées
string liste = "  rouge ,, vert ,  , bleu ";
champs = liste.Split(',', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
Console.WriteLine($"les deux options : {champs.Length} champs [{string.Join("|", champs)}]");

// un séparateur qui est une chaîne
string texte = "pomme -> poire -> abricot";
champs = texte.Split(" -> ");
Console.WriteLine($"séparateur chaîne : [{string.Join("|", champs)}]");

// Join accepte toute collection, pas seulement des chaînes
int[] nombres = [1, 2, 3, 4];
Console.WriteLine($"Join sur des entiers : {string.Join(" + ", nombres)}");

string titre = "Apprentissage du langage C# avec .NET";

// Contains, StartsWith, EndsWith : comparaison exacte par défaut
Console.WriteLine($"Contains(\"langage\") : {titre.Contains("langage")}");
Console.WriteLine($"Contains(\"LANGAGE\") : {titre.Contains("LANGAGE")}");
Console.WriteLine($"StartsWith(\"Apprentissage\") : {titre.StartsWith("Apprentissage")}");
Console.WriteLine($"EndsWith('T') : {titre.EndsWith('T')}");

// on précise le mode de comparaison avec l'énumération StringComparison
Console.WriteLine($"Contains(\"LANGAGE\", OrdinalIgnoreCase) : {titre.Contains("LANGAGE", StringComparison.OrdinalIgnoreCase)}");
Console.WriteLine($"StartsWith(\"apprentissage\", OrdinalIgnoreCase) : {titre.StartsWith("apprentissage", StringComparison.OrdinalIgnoreCase)}");

// égalité : l'opérateur == compare les contenus des chaînes
string reponse = "OUI";
Console.WriteLine($"reponse == \"oui\" : {reponse == "oui"}");
Console.WriteLine($"string.Equals(reponse, \"oui\", OrdinalIgnoreCase) : {string.Equals(reponse, "oui", StringComparison.OrdinalIgnoreCase)}");

// ordre alphabétique : comparaison selon la culture ou selon les codes des caractères
string a = "élève", b = "essai";
Console.WriteLine($"Compare(\"{a}\", \"{b}\", CurrentCulture) : {string.Compare(a, b, StringComparison.CurrentCulture)}");
Console.WriteLine($"Compare(\"{a}\", \"{b}\", Ordinal) : {string.Compare(a, b, StringComparison.Ordinal)}");

string? vide = null;

Console.WriteLine($"[{"abc".PadLeft(8)}] [{"abc".PadRight(8, '.')}] [{new string('-', 8)}]");

// saisie des valeurs du tableau : rend le tableau créé
static double[] Saisie()
{
    // au départ, le tableau est vide
    double[] elements = [];
    // boucle de saisie des éléments du tableau
    while (true)
    {
        Console.Write($"Elément (réel) {elements.Length} du tableau (rien pour terminer) : ");
        string reponse = (Console.ReadLine() ?? "").Trim();
        // fin de saisie si chaîne vide
        if (reponse == "")
        {
            break;
        }
        // vérification de la saisie
        if (!double.TryParse(reponse, out double element))
        {
            Console.WriteLine("Saisie incorrecte, recommencez");
            continue;
        }
        // un élément de plus : on agrandit le tableau d'une case
        Array.Resize(ref elements, elements.Length + 1);
        // et on y range le nouvel élément
        elements[^1] = element;
    }
    return elements;
}

// méthode générique pour afficher les éléments d'un tableau
static void Affiche<T>(string texte, T[] elements)
{
    Console.WriteLine(texte.PadRight(50, '-'));
    foreach (T element in elements)
    {
        Console.WriteLine(element);
    }
}

// recherche d'éléments tapés au clavier dans le tableau
static void Recherche(double[] elements, TypeRecherche type)
{
    while (true)
    {
        Console.Write("Elément cherché (rien pour arrêter) : ");
        string reponse = (Console.ReadLine() ?? "").Trim();
        // fini ?
        if (reponse == "")
        {
            break;
        }
        // vérification
        if (!double.TryParse(reponse, out double element))
        {
            Console.WriteLine("Erreur, recommencez...");
            continue;
        }
        // on cherche l'élément dans le tableau
        int i = type == TypeRecherche.Dichotomique
            ? Array.BinarySearch(elements, element)    // tableau trié
            : Array.IndexOf(elements, element);        // tableau quelconque
        // affichage de la réponse
        Console.WriteLine(i >= 0 ? $"Trouvé en position {i}" : $"Pas dans le tableau ({i})");
    }
}

    5.4. Les collections génériques

    Outre le tableau, il existe diverses classes pour stocker des collections d'éléments. Les collections génériques, apparues avec .NET 2.0, se trouvent dans l'espace de noms [System.Collections.Generic], qui fait partie des [using] implicites. Nous présenterons d'abord deux collections fréquemment utilisées, la liste et le dictionnaire, puis d'autres plus rapidement.

    L'espace de noms [System.Collections] contient les anciennes versions non génériques de ces collections, datant de .NET 1.0 : [ArrayList] (une liste), [Hashtable] (un dictionnaire)... Le cours de 2008 présentait encore [ArrayList]. Ces classes sont aujourd'hui obsolètes : elles stockent des références de type [object], ce qui oblige à transtyper les éléments lus et à encapsuler (boxing) les nombres dans des objets, avec un coût en mémoire et en temps. Les collections génériques n'ont aucun de ces défauts : une [List<int>] range ses entiers directement dans un tableau [int[]] interne, et le compilateur vérifie le type des éléments ajoutés. On ne doit plus utiliser [ArrayList] et [Hashtable] dans du code nouveau.

    5.4.1. La classe générique List<T>

    La classe [System.Collections.Generic.List<T>] permet d'implémenter des collections d'objets de type [T] dont la taille varie au cours de l'exécution du programme. Un objet de type [List<T>] se manipule presque comme un tableau. Ainsi l'élément i d'une liste [l] est-il noté [l[i]].

    Pour une liste [List<T>] où [T] est une classe, la liste stocke les références des objets de type [T], comme un tableau d'objets ; si [T] est un type valeur ([int], [double], structure…), les valeurs elles-mêmes sont stockées dans la liste.

static List<double> Saisie()
{
    // au départ, la liste est vide
    List<double> elements = new();
    // boucle de saisie des éléments de la liste
    while (true)
    {
        Console.Write($"Elément (réel) {elements.Count} de la liste (rien pour terminer) : ");
        string reponse = (Console.ReadLine() ?? "").Trim();
        // fin de saisie si chaîne vide
        if (reponse == "")
        {
            break;
        }
        // vérification de la saisie
        if (!double.TryParse(reponse, out double element))
        {
            Console.WriteLine("Saisie incorrecte, recommencez");
            continue;
        }
        // un élément de plus dans la liste : elle s'agrandit toute seule
        elements.Add(element);
    }
    return elements;
}

// recherche d'éléments tapés au clavier dans la liste
static void Recherche(List<double> elements, TypeRecherche type)
{
    while (true)
    {
        Console.Write("Elément cherché (rien pour arrêter) : ");
        string reponse = (Console.ReadLine() ?? "").Trim();
        // fini ?
        if (reponse == "")
        {
            break;
        }
        // vérification
        if (!double.TryParse(reponse, out double element))
        {
            Console.WriteLine("Erreur, recommencez...");
            continue;
        }
        // on cherche l'élément dans la liste
        int i = type == TypeRecherche.Dichotomique
            ? elements.BinarySearch(element)    // liste triée
            : elements.IndexOf(element);        // liste quelconque
        // affichage de la réponse
        Console.WriteLine(i >= 0 ? $"Trouvé en position {i}" : $"Pas dans la liste ({i})");
    }
}

    5.4.3. La classe Dictionary<TKey,TValue>

    La classe [System.Collections.Generic.Dictionary<TKey,TValue>] permet d'implémenter un dictionnaire. On peut voir un dictionnaire comme un tableau à deux colonnes :

    clé
    valeur
    clé1
    valeur1
    clé2
    valeur2
    ...
    ...

    Dans la classe [Dictionary<TKey,TValue>], les clés sont de type [TKey], les valeurs de type [TValue]. Les clés sont uniques : il ne peut y avoir deux clés identiques. Un tel dictionnaire pourrait ressembler à ceci si les types [TKey] et [TValue] désignaient des classes :

    La valeur associée à la clé [c] d'un dictionnaire [d] est obtenue par la notation [d[c]]. Cette valeur est en lecture et écriture. Ainsi on peut écrire :

    1
2
3
4
5

TKey c = ...;
Dictionary<TKey, TValue> d = new();
d[c] = v;
v = d[c];

    En écriture, [d[c] = v] ajoute le couple (c, v) si la clé [c] n'existe pas, et remplace la valeur associée à [c] sinon. En lecture, si la clé [c] n'existe pas dans le dictionnaire [d], la notation [d[c]] lance une exception [KeyNotFoundException].

    5.5. LINQ

    Le cours de 2008 s'arrêtait au seuil de LINQ, en annonçant ses types anonymes sans les utiliser. LINQ (Language Integrated Query, C# 3, 2007) est un ensemble de méthodes qui permettent d'interroger une collection comme on interroge une base de données : filtrer, trier, regrouper, calculer des totaux... Il s'applique à toute collection implémentant l'interface [IEnumerable<T>] : tableaux, listes, dictionnaires, ensembles, lignes d'un fichier, résultats d'une expression régulière, et, avec Entity Framework Core (chapitre 11), tables d'une base de données. L'espace de noms [System.Linq] fait partie des [using] implicites.

static IEnumerable<int> Pairs(int max)
{

}

    }
}

    • ligne 31 : [OrderByDescending] trie par ordre décroissant ; [ThenBy] (ou [ThenByDescending]) ajoute un critère secondaire, utilisé pour départager les éléments égaux selon le premier critère : durand et laurent, qui ont tous deux 32 ans, sont classés par nom (lignes 23-24) ;

    5.7.2. La sérialisation JSON

    Écrire et relire un fichier binaire donnée par donnée est fastidieux, et le moindre décalage entre l'écriture et la lecture produit des résultats faux. On préfère généralement sérialiser des objets : les transformer automatiquement en une suite d'octets ou de caractères, puis les désérialiser pour les reconstruire.

    .NET proposait pour cela la classe [BinaryFormatter], qui sérialisait des objets dans un format binaire propre à .NET. Elle est aujourd'hui supprimée : elle a été déclarée obsolète en .NET 5 et son implémentation a été retirée en .NET 9, car désérialiser des données provenant d'une source non sûre avec [BinaryFormatter] permettait d'exécuter du code arbitraire. Microsoft recommande de la remplacer par la sérialisation JSON de la bibliothèque [System.Text.Json], intégrée à .NET depuis .NET Core 3.0.

    JSON (JavaScript Object Notation) est un format texte, lisible, et universel : c'est le format d'échange des services web (chapitre 13) et de nombreux fichiers de configuration. Un objet y est écrit entre accolades sous la forme de couples "propriété": valeur, un tableau entre crochets.

    La classe statique [System.Text.Json.JsonSerializer] a deux méthodes principales :

    méthode

    [string Serialize<T>(T value, JsonSerializerOptions? options = null)]
    rend le texte JSON représentant l'objet [value]
    [T? Deserialize<T>(string json, JsonSerializerOptions? options = null)]
    reconstruit un objet de type [T] à partir du texte JSON [json] ; lance une [JsonException] si le texte est incorrect

    5.8. Les expressions régulières

    La classe [System.Text.RegularExpressions.Regex] permet l'utilisation d'expressions régulières. Celles-ci permettent de tester le format d'une chaîne de caractères. Ainsi on peut vérifier qu'une chaîne représentant une date est bien au format jj/mm/aa. On utilise pour cela un modèle et on compare la chaîne à ce modèle. Dans cet exemple, j, m et a doivent être des chiffres. Le modèle d'un format de date valide est alors [\d\d/\d\d/\d\d] où le symbole [\d] désigne un chiffre. Les symboles utilisables dans un modèle sont les suivants :

    caractère
    description
    [\]
    marque le caractère suivant comme caractère spécial ou littéral. Par exemple, [n] correspond au caractère n, [\n] correspond à un caractère de nouvelle ligne, [\\] correspond à \, [\(] correspond à (
    [^]
    correspond au début de la chaîne
    [$]
    correspond à la fin de la chaîne
    [*]
    correspond à l'élément précédent zéro fois ou plusieurs fois. Ainsi [zo*] correspond à z ou à zoo
    [+]
    correspond à l'élément précédent une ou plusieurs fois. Ainsi [zo+] correspond à zoo, mais pas à z
    [?]
    correspond à l'élément précédent zéro ou une fois. Par exemple, [a?ve?] correspond à ve dans lever
    [.]
    correspond à tout caractère unique, sauf le caractère de nouvelle ligne
    [(modèle)]
    recherche le modèle et mémorise la correspondance (un groupe). La sous-chaîne correspondante peut être extraite de la collection [Groups] du résultat. Pour trouver des correspondances avec des caractères entre parenthèses, utilisez [\(] ou [\)]
    [x|y]
    correspond soit à x, soit à y. Par exemple, [z|foot] correspond à z ou à foot ; [(z|f)oo] correspond à zoo ou à foo
    [{n}]
    n est un entier non négatif. Correspond exactement n fois à l'élément précédent. Par exemple, [o{2}] ne correspond pas à o dans Bob, mais aux deux premiers o de fooooot
    [{n,}]
    correspond au moins n fois à l'élément précédent. Par exemple, [o{2,}] ne correspond pas à o dans Bob, mais à tous les o de fooooot. [o{1,}] équivaut à [o+] et [o{0,}] équivaut à [o*]
    [{n,m}]
    correspond au moins n fois et au plus m fois à l'élément précédent. Par exemple, [o{1,3}] correspond aux trois premiers o de foooooot ; [o{0,1}] équivaut à [o?]
    [xyz]
    jeu de caractères : correspond à l'un des caractères indiqués. Par exemple, [abc] correspond à a dans plat
    [^xyz]
    jeu de caractères négatif : correspond à tout caractère non indiqué. Par exemple, [^abc] correspond à p dans plat
    [a-z]
    plage de caractères : correspond à tout caractère de la série spécifiée, ici une lettre minuscule non accentuée
    [^m-z]
    plage de caractères négative : correspond à tout caractère ne se trouvant pas entre m et z
    [\b]
    correspond à une limite de mot, c'est-à-dire à la position entre un caractère de mot et un caractère qui n'en est pas un. Par exemple, [er\b] correspond à er dans lever, mais pas à er dans verbe
    [\B]
    correspond à une position qui n'est pas une limite de mot. [en*t\B] correspond à ent dans « bien entendu »
    [\d]
    correspond à un chiffre ; équivaut à [0-9] (avec .NET, aussi aux chiffres des autres alphabets Unicode)
    [\D]
    correspond à un caractère qui n'est pas un chiffre
    [\f], [\n], [\r], [\t], [\v]
    correspondent respectivement aux caractères saut de page, nouvelle ligne, retour chariot, tabulation, tabulation verticale
    [\s]
    correspond à tout espace blanc : espace, tabulation, saut de page, nouvelle ligne… Équivaut à [ \f\n\r\t\v], plus les autres espaces d'Unicode (espace insécable…)
    [\S]
    correspond à tout caractère qui n'est pas un espace blanc
    [\w]
    correspond à tout caractère de mot : lettre (accentuée ou non), chiffre ou trait de soulignement
    [\W]
    correspond à tout caractère qui n'est pas un caractère de mot
    [\num]
    num est un entier positif : fait référence au groupe n° num. Par exemple, [(.)\1] correspond à deux caractères identiques consécutifs
    [\xnn], [\unnnn]
    correspond au caractère de code hexadécimal nn (2 chiffres) ou nnnn (4 chiffres). Par exemple, [\x41] correspond à A

    Un élément dans un modèle peut être présent en 1 ou plusieurs exemplaires. Considérons quelques exemples autour du symbole [\d] qui représente 1 chiffre :

    modèle
    signification
    [\d]
    un chiffre
    [\d?]
    0 ou 1 chiffre
    [\d*]
    0 ou davantage de chiffres
    [\d+]
    1 ou davantage de chiffres
    [\d{2}]
    2 chiffres
    [\d{3,}]
    au moins 3 chiffres
    [\d{5,7}]
    entre 5 et 7 chiffres

    On peut préciser où on recherche le modèle dans la chaîne :

    modèle
    signification
    [^modèle]
    le modèle commence la chaîne
    [modèle$]
    le modèle finit la chaîne
    [^modèle$]
    le modèle commence et finit la chaîne
    [modèle]
    le modèle est cherché partout dans la chaîne, en commençant par le début de celle-ci
    chaîne recherchée
    modèle
    une chaîne se terminant par un point d'exclamation
    [!$]
    une chaîne se terminant par un point
    [\.$]
    une chaîne commençant par la séquence //
    [^//]
    une chaîne ne comportant qu'un mot, éventuellement suivi ou précédé d'espaces
    [^\s*\w+\s*$]
    une chaîne ne comportant que deux mots, éventuellement suivis ou précédés d'espaces
    [^\s*\w+\s+\w+\s*$]
    une chaîne contenant le mot secret
    [\bsecret\b]

    Les sous-ensembles d'un modèle peuvent être « récupérés ». Ainsi, non seulement on peut vérifier qu'une chaîne correspond à un modèle particulier, mais on peut récupérer dans cette chaîne les éléments correspondant aux sous-ensembles du modèle qui ont été entourés de parenthèses. Ainsi, si on analyse une chaîne contenant une date jj/mm/aa et si on veut de plus récupérer les éléments jj, mm, aa de cette date, on utilisera le modèle [(\d\d)/(\d\d)/(\d\d)].

    Dans le code C#, un modèle est écrit de préférence dans une chaîne verbatim [@"..."] : les nombreux caractères [] des modèles n'ont alors pas à être doublés. Avec une chaîne ordinaire, il faudrait écrire ["\\d+"] au lieu de [@"\d+"].

    • lignes 39-51 : chaque modèle est déclaré par une méthode statique partielle ([partial]), sans corps, rendant un [Regex], et précédée de l'attribut [GeneratedRegex]. Le générateur de source écrit le corps de la méthode dans une autre partie de la classe, elle aussi déclarée [partial]. Depuis C# 13 et .NET 9, on peut aussi déclarer une propriété partielle : [[GeneratedRegex(...)] private static partial Regex Heure { get; }] ;
    • ligne 5 : on utilise la méthode comme un objet [Regex] ordinaire ;
    • ligne 46 : le second paramètre de l'attribut est une combinaison d'options [RegexOptions]. [IgnoreCase] ignore la casse : « OUI » et « Oui » correspondent au modèle ;
    • ligne 17 : les options s'utilisent de la même façon avec les méthodes de [Regex]. [Multiline] fait correspondre [^] et [$] au début et à la fin de chaque ligne de la chaîne, et non plus seulement au début et à la fin de la chaîne. D'autres options sont utiles : [Singleline] ([.] correspond aussi au saut de ligne), [IgnorePatternWhitespace] (les espaces du modèle sont ignorés, ce qui permet de l'écrire sur plusieurs lignes, commentées), [ExplicitCapture] (seuls les groupes nommés sont mémorisés). Elles se combinent avec l'opérateur [|] ;
    • ligne 50 : le modèle [^(a+)+$] est pathologique : appliqué à une suite de a terminée par un autre caractère, le moteur d'expressions régulières essaie toutes les façons de répartir les a entre les répétitions du groupe avant de conclure à l'échec. Leur nombre double à chaque a supplémentaire : avec 30 a, il y en a environ un milliard. On parle de retour arrière catastrophique. Un tel modèle, appliqué à des chaînes saisies par des utilisateurs, est une faille de sécurité : quelques requêtes suffisent à bloquer un serveur. Le paramètre [matchTimeoutMilliseconds] fixe un délai d'expiration de 100 ms : au-delà, la recherche est abandonnée avec une exception [RegexMatchTimeoutException] (ligne 6) ;
    • ligne 35 : l'option [NonBacktracking] (.NET 7) utilise un autre moteur, qui garantit un temps de recherche proportionnel à la longueur de la chaîne. Il ne permet pas certaines constructions (les références arrière [\1], par exemple), mais il répond ici immédiatement.

    On retiendra qu'il faut fixer un délai d'expiration, ou utiliser [NonBacktracking], dès que le modèle ou la chaîne explorée proviennent de l'extérieur du programme.

    public int Calculer(bool marie, int nbEnfants, int salaire)
    {
        // calcul du nombre de parts
        decimal nbParts = (decimal)nbEnfants / 2 + (marie ? 2 : 1);
        if (nbEnfants >= 3)
        {
            nbParts += 0.5m;
        }
        // calcul du revenu imposable et du quotient familial
        decimal revenu = 0.72m * salaire;

        // recherche de la tranche d'impôt : la dernière sert si aucune limite ne convient
        TrancheImpot[] tranches = TranchesImpot;
        TrancheImpot tranche = tranches[^1];
        for (int i = 0; i < tranches.Length - 1; i++)

            {

                break;
            }
        }
        // calcul de l'impôt
        return (int)(revenu * tranche.CoeffR - nbParts * tranche.CoeffN);
    }
}

namespace ImpotsV3;

// les tranches d'impôt lues dans un fichier texte de lignes limite:coeffR:coeffN
public partial class FileImpot : AbstractImpot
{
    // le séparateur des champs : le caractère : entouré d'espaces éventuels
    [GeneratedRegex(@"\s*:\s*")]
    private static partial Regex Separateur();

    // les tranches d'impôt lues dans le fichier
    private readonly TrancheImpot[] tranchesImpot;

    // implémentation de la propriété abstraite de la classe parent
    protected override TrancheImpot[] TranchesImpot => tranchesImpot;

    public FileImpot(string nomFichier)
    {
        // le nom du fichier, sans son chemin, pour les messages d'erreur
        string nom = Path.GetFileName(nomFichier);
        // les tranches lues ; on ne connaît pas leur nombre à l'avance
        List<TrancheImpot> tranches = [];
        try
        {
            int numLigne = 0;
            foreach (string ligneLue in File.ReadLines(nomFichier))
            {
                numLigne++;
                string ligne = ligneLue.Trim();
                // on ignore les lignes vides
                if (ligne == "")
                {
                    continue;
                }
                // la ligne doit avoir trois champs
                string[] champs = Separateur().Split(ligne);
                if (champs.Length != 3)
                {
                    throw new ImpotException($"Ligne n° {numLigne} incorrecte ({ligne})")
                    {
                        Code = (int)CodeErreur.Ligne
                    };
                }
                // trois nombres décimaux positifs ou nuls, écrits avec un point décimal
                CodeErreur code = 0;
                if (!Lire(champs[0], out decimal limite)) code |= CodeErreur.Champ1;
                if (!Lire(champs[1], out decimal coeffR)) code |= CodeErreur.Champ2;
                if (!Lire(champs[2], out decimal coeffN)) code |= CodeErreur.Champ3;
                if (code != 0)
                {
                    throw new ImpotException($"Ligne n° {numLigne} incorrecte ({ligne})")
                    {
                        Code = (int)code
                    };
                }
                // on mémorise la nouvelle tranche d'impôt
                tranches.Add(new TrancheImpot(limite, coeffR, coeffN));
            }
        }
        catch (Exception e) when (e is IOException or UnauthorizedAccessException)
        {
            // erreur d'accès au fichier : on l'encapsule dans une ImpotException
            throw new ImpotException($"Erreur lors de la lecture du fichier {nom}", e)
            {
                Code = (int)CodeErreur.Acces
            };
        }
        // il faut au moins une tranche
        if (tranches.Count == 0)
        {
            throw new ImpotException($"Le fichier {nom} ne contient aucune tranche")
            {
                Code = (int)CodeErreur.Ligne
            };
        }
        // on transfère la liste dans le tableau des tranches
        tranchesImpot = tranches.ToArray();
    }

    // conversion d'un champ en decimal >= 0, indépendamment de la culture de la machine
    private static bool Lire(string champ, out decimal valeur) =>
        decimal.TryParse(champ, NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture, out valeur);
}

    Commentaires :

    • ligne 7 : la classe [FileImpot] dérive de la classe [AbstractImpot], comme le faisait dans la version 2 la classe [HardwiredImpot]. Elle est déclarée [partial] parce qu'elle contient une expression régulière générée ;
    • lignes 10-11 : l'expression régulière du séparateur des champs d'une ligne limite:coeffR:coeffN : le caractère [:], précédé et suivi d'un nombre quelconque d'espaces ;
    • lignes 14-17 : les tranches lues, rendues par la propriété [TranchesImpot] qui redéfinit la propriété abstraite de [AbstractImpot] ;
    • ligne 19 : le constructeur reçoit le nom du fichier texte contenant les données. Son rôle est de remplir le tableau [tranchesImpot] ;
    • ligne 22 : le nom du fichier sans son chemin, utilisé dans les messages d'erreur. Le constructeur reçoit en effet un chemin complet, qu'il n'est pas utile d'afficher à l'utilisateur ;
    • ligne 24 : la lecture d'un fichier texte est séquentielle : on ne connaît le nombre de lignes qu'après avoir lu la totalité du fichier. On ne peut donc pas dimensionner le tableau à l'avance : on mémorise provisoirement les tranches dans une liste ;
    • ligne 28 : le fichier est lu ligne par ligne avec [File.ReadLines], qui ouvre et ferme le fichier lui-même. Le cours de 2008 utilisait un [StreamReader] ;
    • lignes 38-43 : la ligne est découpée en champs grâce à l'expression régulière ; s'il n'y a pas trois champs, une exception [ImpotException] de code [Ligne] est lancée. Le cours de 2008 mémorisait l'erreur dans une variable, sortait de la boucle, puis lançait l'exception après la fermeture du fichier : la lancer immédiatement est plus simple, et [File.ReadLines] ferme le fichier dans tous les cas, car la boucle [foreach] libère son énumérateur même lorsqu'une exception l'interrompt ;
    • lignes 47-55 : conversion des trois champs en nombres décimaux. Les erreurs sont cumulées dans la variable [code] avec l'opérateur [|=], puis signalées ensemble ;
    • lignes 83-84 : la conversion d'un champ. [NumberStyles.AllowDecimalPoint] n'autorise que des chiffres et un point décimal : ni signe, ni espaces, ni séparateur des milliers. Les nombres négatifs sont ainsi refusés, ce qui valide les données en même temps qu'on les convertit. [CultureInfo.InvariantCulture] impose le point comme séparateur décimal, quelle que soit la culture de la machine ;
    • lignes 62-67 : les erreurs d'accès au fichier ([IOException] et ses dérivées, comme [FileNotFoundException], ou [UnauthorizedAccessException] pour des droits insuffisants) sont encapsulées dans une [ImpotException] de code [Acces]. Le filtre d'exception [when (...)] (C# 6) n'intercepte que ces exceptions : les [ImpotException] lancées dans la boucle ne sont pas interceptées et sortent du constructeur telles quelles. Le motif [e is IOException or UnauthorizedAccessException] est un motif de type combiné par [or] (C# 9) ;
    • lignes 71-79 : un fichier vide est refusé ; sinon la liste est transférée dans le tableau des tranches, ce qui était le but du constructeur.

    Encapsuler les exceptions de bas niveau ([IOException]) dans une exception propre à l'application ([ImpotException]) permet au code appelant de ne traiter qu'un seul type d'exception, quelle que soit la source des données : un fichier texte, un fichier JSON et, plus tard dans le cours, une base de données.

            };

            };

    Salaire : salaire annuel en euros
    """;

// le fichier de données est cherché à côté de l'exécutable
string nomFichier = args.Length > 0 ? args[0] : "DataImpot.txt";
string chemin = Path.Combine(AppContext.BaseDirectory, nomFichier);
Console.WriteLine($"Tranches d'impôt lues dans [{nomFichier}]");

// création d'un objet IImpot ; la classe dépend de l'extension du fichier
IImpot impot;
try
{
    impot = Path.GetExtension(nomFichier).ToLower() switch
    {
        ".json" => new JsonImpot(chemin),
        _ => new FileImpot(chemin)
    };
}
catch (ImpotException e)
{
    // affichage de l'erreur ; le code est affiché sous la forme d'une combinaison de CodeErreur
    string origine = e.InnerException is null ? "" : $", Exception d'origine : {e.InnerException.GetType().Name}";
    Console.WriteLine($"L'erreur suivante s'est produite : [Code={(CodeErreur)e.Code}, Message={e.Message}{origine}]");
    // arrêt du programme
    return 1;
}

// boucle de saisie
while (true)
{
    // on demande les paramètres du calcul de l'impôt
    Console.Write("Paramètres du calcul de l'impôt au format : Marié (o/n) NbEnfants Salaire ou rien pour arrêter : ");
    string parametres = (Console.ReadLine() ?? "").Trim();
    // quelque chose à faire ?
    if (parametres == "")
    {
        break;
    }
    // vérification du nombre de champs de la ligne saisie
    string[] champs = parametres.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    if (champs.Length != 3)
    {
        Console.WriteLine(syntaxe);
        continue;
    }
    // vérification de la validité des paramètres
    // marié
    string marie = champs[0].ToLower();
    if (marie != "o" && marie != "n")
    {
        Console.WriteLine(syntaxe + "\nArgument marié incorrect : tapez o ou n");
        continue;
    }
    // nbEnfants
    if (!int.TryParse(champs[1], out int nbEnfants) || nbEnfants < 0)
    {
        Console.WriteLine(syntaxe + "\nArgument NbEnfants incorrect : tapez un entier positif ou nul");
        continue;
    }
    // salaire
    if (!int.TryParse(champs[2], out int salaire) || salaire < 0)
    {
        Console.WriteLine(syntaxe + "\nArgument salaire incorrect : tapez un entier positif ou nul");
        continue;
    }
    // les paramètres sont corrects : on calcule l'impôt
    Console.WriteLine($"Impôt={impot.Calculer(marie == "o", nbEnfants, salaire)} euros");
}
return 0;

    Commentaires :

    • ligne 14 : le nom du fichier de données est passé en argument ; par défaut, c'est [DataImpot.txt] ;
    • ligne 15 : le fichier est cherché dans le dossier de l'exécutable, [AppContext.BaseDirectory], où il a été copié lors de la compilation. Ainsi, le programme trouve ses données quel que soit le dossier d'où on le lance, ce qui n'était pas le cas des applications fichier unique de ce chapitre ;
    • lignes 22-25 : une expression [switch] (chapitre 3) choisit la classe à instancier selon l'extension du fichier. Les deux branches rendent des types différents, [JsonImpot] et [FileImpot] : le compilateur en déduit le type de l'expression grâce à la variable de destination [impot], de type [IImpot] (expression [switch] à type cible). Le reste du programme ne connaît que l'interface [IImpot] et ignore d'où viennent les données ;
    • lignes 28-34 : la création de l'objet peut lancer une [ImpotException], qui est affichée avant l'arrêt du programme. Le code est converti en [CodeErreur] pour être affiché en clair ; l'exception d'origine, s'il y en a une, est indiquée par son type (son message contient le chemin complet du fichier) ;
    • lignes 37-76 : la boucle de dialogue est exactement celle de la version 2.

    5.10. Conclusion

    Ce chapitre a présenté les classes de .NET dont on se sert dans presque tous les programmes :

    • les chaînes [string], immuables, et [StringBuilder] pour les construire par morceaux ; l'interpolation avec largeurs et formats, les chaînes brutes ; les vues [ReadOnlySpan<char>] pour le code critique ;
    • les tableaux et la classe [Array] ;
    • les collections génériques [List<T>], [Dictionary<TKey,TValue>], [HashSet<T>], [Queue<T>], [Stack<T>], [PriorityQueue<TElement,TPriority>], et leurs interfaces en lecture seule ; les collections non génériques [ArrayList] et [Hashtable] sont obsolètes ;
    • LINQ, ses séquences [IEnumerable<T>], ses itérateurs et son exécution différée ;
    • les fichiers texte ([StreamReader], [StreamWriter], [File]), les fichiers binaires ([BinaryWriter], [BinaryReader]) et la sérialisation JSON, qui remplace la sérialisation binaire de [BinaryFormatter], supprimée de .NET ;
    • les expressions régulières, de préférence générées à la compilation et toujours protégées par un délai d'expiration lorsqu'elles traitent des données extérieures.

    L'application exemple lit maintenant ses données dans un fichier texte ou JSON. Le chapitre suivant la réorganise en couches : la lecture des données, le calcul de l'impôt et le dialogue avec l'utilisateur y deviendront des composants indépendants.
