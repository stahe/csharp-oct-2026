    1. Introduction

    Le PDF du document est ICI.

    Les codes du document sont ICI.

    Ce document est un produit de l'IA Claude d'Anthropic. C'est la réécriture, pour le langage C# 14 et la plateforme .NET 10, du cours Apprentissage du langage C# version 3.0 avec le framework .NET 3.5 écrit par Serge Tahé en mai 2008. Il en reprend le plan, les exemples et le fil rouge, et en actualise le langage, les bibliothèques et les outils :

    • le cours de 2008 utilisait C# 3.0 et le framework .NET 3.5, sous Windows, avec Visual C# 2008 Express. Depuis, C# a connu onze versions majeures (de C# 4.0 en 2010 à C# 14 en 2025) et la plateforme .NET a été entièrement réécrite : elle est devenue libre, multiplateforme (Windows, Linux, macOS) et publiée chaque année. Ce document utilise .NET 10 (novembre 2025, version à support long) et C# 14 ;
    • le chapitre sur les interfaces graphiques Windows Forms a été supprimé : les applications de gestion s'écrivent aujourd'hui le plus souvent avec des interfaces web. Le chapitre « Evénements utilisateur », qui le suivait, est devenu un chapitre sur les délégués, les expressions lambda et les événements, sans formulaires ;
    • deux chapitres sont nouveaux : la programmation asynchrone (les tâches [Task] et les mots clés [async] / [await], apparus en 2012 avec C# 5) et Entity Framework Core, l'outil de correspondance objet / relationnel de .NET. Le chapitre sur les classes .NET d'usage courant présente désormais LINQ (le cours de 2008 indiquait explicitement qu'il ne l'abordait pas) ;
    • les outils ont changé : l'éditeur [VS Code] (ou l'IDE [Visual Studio 2026]) et la commande [dotnet] remplacent Visual C# 2008 Express ; le framework de tests [MSTest] remplace [NUnit 2] ; l'injection de dépendances de [Microsoft.Extensions.DependencyInjection] remplace [Spring.NET] ; le SGBD [MySQL] (fourni par [Laragon]) et le connecteur [MySqlConnector] remplacent SQL Server 2005 Express ; la classe [HttpClient] remplace [WebClient] et [WebRequest], devenues obsolètes ; les services web REST / JSON écrits avec ASP.NET Core remplacent les services web SOAP [ASMX] ;
    • tout ce qui est devenu obsolète a été retiré ou signalé comme tel, et chaque chapitre présente, au moment où elles servent, les nouveautés du langage et de la plateforme.

    Ce document n'est pas un cours exhaustif. Comme celui de 2008, il est destiné à des personnes connaissant déjà la programmation et qui veulent découvrir les bases de C#. Il procède par l'exemple : plus de deux cents programmes (près de trois cents fichiers C#), courts pour la plupart, commentés ligne par ligne.

    1.1. C# et .NET de 2002 à 2026

    C# a été rendu public en février 2002, en même temps que la plateforme .NET 1.0 de Microsoft à laquelle il est lié. La plateforme .NET est un environnement d'exécution analogue à la machine virtuelle Java : les compilateurs des langages .NET (C#, F#, VB.NET) produisent un code intermédiaire (IL, « Intermediate Language ») que la machine virtuelle .NET (le CLR, « Common Language Runtime ») compile à la volée en code machine. Toutes les classes de la plateforme sont disponibles pour tous les langages .NET.

    En 2008, le cours écrivait que .NET ne s'exécutait que sous Windows et que le projet Mono permettait de l'utiliser, partiellement, sous Unix et Linux. La situation a profondément changé :

    • 2016 : .NET Core 1.0. Microsoft publie une nouvelle implémentation de .NET, libre (licence MIT, code sur GitHub) et multiplateforme : Windows, Linux et macOS. L'ancien « framework .NET » (.NET Framework 4.x) reste maintenu pour les anciennes applications Windows mais n'évolue plus ;
    • 2020 : .NET 5. .NET Core devient simplement « .NET » : une seule plateforme pour tous les usages (console, web, bureau, mobile, nuage) ;
    • depuis 2020 : une nouvelle version de .NET paraît chaque année en novembre. Les versions paires (.NET 6, 8, 10) sont à support long (LTS, trois ans) ; les versions impaires (.NET 7, 9) sont à support standard (STS : dix-huit mois, portés à deux ans à partir de .NET 9). Chaque version de .NET apporte une nouvelle version de C# ;
    • novembre 2025 : .NET 10 (LTS) et C# 14, utilisés dans ce document. .NET 10 est supporté jusqu'en novembre 2028.

    Le cours de 2008 écrivait aussi qu'en 2002, C# était largement une copie de Java et qu'on passait aisément de l'un à l'autre, mais que les deux langages avaient depuis pris chacun leurs spécificités. L'écart s'est creusé : C# a intégré au fil des versions des idées venues des langages fonctionnels (expressions lambda, LINQ, filtrage par motif, records, types immuables), l'asynchronisme ([async] / [await], que JavaScript, Python ou Rust ont ensuite repris), et un système de types qui détecte à la compilation les références nulles.

    1.3. Le fil rouge : le calcul de l'impôt

    Comme en 2008, un même problème est repris tout au long du document : le calcul de l'impôt sur le revenu d'un contribuable n'ayant que son salaire à déclarer. Le barème utilisé est celui du cours d'origine (revenus 2003) : il n'est plus d'actualité, mais il suffit à notre propos, qui est d'écrire la même application de plusieurs façons. Elle est construite en neuf versions :

    Version
    Chapitre
    Contenu
    1
    3
    un programme unique : saisies validées, calcul, affichage

    3

    À partir de la version 5, les versions suivantes réutilisent les couches de la version 5 et ne remplacent que la couche qui change : c'est tout l'intérêt de l'architecture en couches présentée au chapitre 6.

    Les petits programmes sont des applications fichier unique : un simple fichier [.cs], exécuté par la commande [dotnet run fichier.cs] (chapitre 2). Les programmes de plusieurs fichiers sont des projets ([.csproj]) regroupés dans une solution ([.slnx]) par chapitre.

    Tous les programmes du document ont été compilés sans erreur ni avertissement avec le SDK .NET 10, et exécutés. Les résultats reproduits dans le document sont ceux de ces exécutions. Ils ont été obtenus en culture française (fr-FR), comme sur un poste Windows français : les nombres réels s'affichent avec une virgule décimale et les dates en français. Deux remarques :

    • les messages d'erreur de la plateforme .NET (les messages des exceptions) sont en anglais : .NET ne fournit pas de traduction française de ces messages ;
    • les exemples ont été exécutés sous Linux. Pour l'essentiel, cela ne change rien : .NET est multiplateforme. Les quelques différences (chemins de fichiers avec des / au lieu de \, fins de ligne) sont signalées là où elles apparaissent.

    Les résultats des programmes multithreads, asynchrones ou réseau, ainsi que les durées mesurées, peuvent varier d'une exécution à l'autre : les commentaires portent sur ce qui est reproductible.
