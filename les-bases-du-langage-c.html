    3. Les bases du langage C#

    3.1. Introduction

    Nous traitons C# d'abord comme un langage de programmation classique. Nous aborderons les classes dans le chapitre suivant. Dans un programme, on trouve deux choses :

    • des données ;
    • les instructions qui les manipulent.

    On s'efforce généralement de séparer les données des instructions :

    Tous les exemples de ce chapitre sont des applications fichier unique : un seul fichier [.cs], sans fichier projet [.csproj], que l'on exécute avec la commande [dotnet run bases-01.cs]. Cette possibilité, apparue avec .NET 10, a été présentée au chapitre précédent. Les exemples se trouvent dans le dossier [03-bases] du code du cours. Ils s'exécutent en culture française (fr-FR), comme sur un poste Windows français : les nombres réels sont affichés avec une virgule décimale.

    • le programme ne contient ni classe ni méthode : les instructions sont écrites directement dans le fichier. On appelle cela des instructions de haut niveau (C# 9, 2020). Un seul fichier d'un programme peut en contenir ;
    • ligne 3 : la méthode [WriteLine] de la classe [Console] écrit une ligne à l'écran ;
    • ligne 5 : la classe [Console] appartient à l'espace de noms [System]. Son nom complet est [System.Console]. Un espace de noms regroupe des types apparentés, comme un dossier regroupe des fichiers ;
    • ligne 5 : le programme dispose d'un tableau [args] contenant les arguments de la ligne de commande. Nous y reviendrons dans la section « Arguments du programme principal ». Le nombre d'éléments du tableau est [args.Length]. L'opérateur + concatène ici une chaîne et un nombre : le nombre est d'abord converti en chaîne.

    Commentaires :

    • ligne 2 : la directive [using] importe l'espace de noms [System]. On peut alors écrire [Console] au lieu de [System.Console] ;
    • ligne 4 : la classe est placée dans l'espace de noms [Bases]. Depuis C# 10, on peut écrire [namespace Bases;] (espace de noms de portée fichier) : tout le fichier appartient alors à cet espace de noms, sans accolades ni niveau d'indentation supplémentaire. C'est la forme que nous utiliserons désormais ;
    • ligne 6 : en C#, tout code appartient à une classe. La classe s'appelle ici [Program] ;
    • ligne 9 : la méthode statique [Main] est le point d'entrée du programme : c'est elle que le système exécute au lancement. Son paramètre [args] reçoit les arguments de la ligne de commande.

    Les deux programmes sont équivalents. Lorsqu'il rencontre des instructions de haut niveau, le compilateur génère lui-même une classe et une méthode [Main] qui contiennent ces instructions, ainsi que le paramètre [string[] args]. Les instructions de haut niveau ne sont donc qu'une écriture abrégée de la forme classique. Elles conviennent bien aux petits programmes de ce chapitre ; la forme classique reste utile lorsqu'on veut contrôler la classe qui contient [Main].

    Ci-dessus, on a mis en face des types C# leur type .NET équivalent, avec la mention (S) si ce type est une structure et (C) si c'est une classe. On découvre qu'il y a deux noms possibles pour un entier sur 32 bits : [int] et [Int32]. Le type [int] est un mot clé du langage C#. [Int32] est une structure appartenant à l'espace de noms [System] : son nom complet est [System.Int32]. Le type [int] est un alias C# qui désigne la structure .NET [System.Int32]. De même, le type C# [string] est un alias du type .NET [System.String]. [System.String] est une classe et non une structure. Les deux notions sont proches, avec cependant la différence fondamentale suivante :

    • une variable de type structure contient directement sa valeur : on parle de type valeur ;
    • une variable de type classe contient l'adresse de l'objet (sa référence) : on parle de type référence.

    S'y ajoutent deux types moins courants :

    • [nint] et [nuint] (C# 9) sont des entiers signé et non signé dont la taille est celle d'une adresse mémoire : 4 octets sur un système 32 bits, 8 octets sur un système 64 bits. Ils servent surtout à dialoguer avec du code natif ;
    • [System.Half] (.NET 5) est un réel codé sur 2 octets, de faible précision, utilisé en calcul graphique et en apprentissage automatique. Ce n'est pas un type prédéfini du langage : il n'a pas de mot clé C#.

    Une structure, comme une classe, est un type complexe ayant des attributs et des méthodes. Ainsi, on peut écrire :

    1

Parmi les propriétés de cet objet, [FullName] est le nom complet du type. Le littéral 3 est donc un objet plus complexe qu'il n'y paraît à première vue. Le point d'interrogation de [string?] sera expliqué un peu plus loin.

    Dans le code source, les réels s'écrivent toujours avec un point décimal, quelle que soit la culture du système. Depuis C# 7, on peut écrire les entiers en binaire (préfixe [0b]) et séparer les groupes de chiffres par le caractère _ pour améliorer la lisibilité : [1_000_000] est l'entier un million.

    Une chaîne littérale classique peut contenir des séquences d'échappement introduites par le caractère \ : "\n" représente la marque de fin de ligne et non la succession des deux caractères \ et n, "\t" une tabulation, "\"" un guillemet, "\\" le caractère \ lui-même. Pour écrire le chemin Windows c:\chap1\paragraph3, il faut donc écrire "c:\\chap1\\paragraph3". On peut aussi écrire @"c:\chap1\paragraph3" : la syntaxe @"texte" demande que le texte soit pris exactement comme il est écrit, sans interpréter le caractère \. On appelle cela une chaîne verbatim.

    C# offre aujourd'hui deux autres formes de chaînes :

    • la chaîne interpolée (C# 6) $"..." : les expressions placées entre accolades sont évaluées et leur valeur est insérée dans la chaîne. Une expression peut être suivie d'un format après le caractère deux-points : [$"{d1:F2}"] affiche le réel [d1] avec deux décimales. C'est la façon la plus lisible de construire une chaîne et nous l'utiliserons désormais à la place des formats {0}, {1}, ... ;
    • la chaîne brute (C# 11) """...""" : elle commence et se termine par au moins trois guillemets. Elle peut contenir des guillemets et des \ sans échappement, et s'étendre sur plusieurs lignes. Les espaces qui précèdent les guillemets fermants sont retirés de chaque ligne, ce qui permet d'indenter le texte avec le code. Elle est très pratique pour écrire du JSON, du SQL ou du HTML.

    3.3.3. Déclaration des données

    3.3.3.1. Rôle des déclarations

    Un programme manipule des données caractérisées par un nom et un type. Ces données sont stockées en mémoire. Au moment de la traduction du programme, le compilateur affecte à chaque donnée un emplacement en mémoire caractérisé par une adresse et une taille. Il le fait en s'aidant des déclarations faites par le programmeur. Par ailleurs, celles-ci permettent au compilateur de détecter des erreurs de programmation. Ainsi l'opération [x = x * 2;] sera déclarée erronée si [x] est une chaîne de caractères.

    3.3.3.2. Déclaration des constantes

    La syntaxe de déclaration d'une constante est la suivante :

    1
    const type nom = valeur;

    Par exemple :

    1
    const double TauxTva = 0.2;

    Pourquoi déclarer des constantes ?

    • la lecture du programme est plus aisée si l'on a donné à la constante un nom significatif ;
    • la modification du programme est plus aisée si la « constante » vient à changer. Ainsi, si le taux de TVA passe à 0,25, la seule modification à faire sera celle de l'instruction qui définit sa valeur : [const double TauxTva = 0.25;]. Si l'on avait utilisé 0.2 explicitement dans le programme, ce serait de nombreuses instructions qu'il faudrait modifier.

    La valeur d'une constante doit être connue à la compilation : un nombre, une chaîne, un booléen ou une expression calculable à partir d'autres constantes. Par convention, en .NET, les noms des constantes commencent par une majuscule.

    3.3.3.3. Déclaration des variables

    Une variable est identifiée par un nom et se rapporte à un type de données. C# fait la différence entre majuscules et minuscules : les variables [FIN] et [fin] sont différentes.

    Les variables peuvent être initialisées lors de leur déclaration. La syntaxe de déclaration d'une ou plusieurs variables est :

    1
    type variable1 = valeur1, variable2 = valeur2, ...;

    où [type] est un type prédéfini ou un type défini par le programmeur. L'initialisation est facultative ; en revanche, C# refuse qu'on utilise la valeur d'une variable locale qui n'a pas encore reçu de valeur.

    On peut également ne pas préciser le type d'une variable en utilisant le mot clé [var] à la place du type :

    1
    var variable1 = valeur1;

    Le mot clé [var] ne veut pas dire que la variable n'a pas de type précis : elle a le type de la valeur qui lui est affectée, déterminé par le compilateur. L'initialisation est ici obligatoire, afin que le compilateur puisse en déduire le type. On utilise [var] lorsque le type est évident à la lecture de la valeur.

    3.3.4. Les types nullables

    Une variable d'un type valeur, comme [int], contient toujours une valeur. Il est parfois utile de pouvoir exprimer l'absence de valeur : un âge inconnu, un champ non renseigné dans une base de données. Le type [int?] (C# 2) est le type [int] auquel on ajoute la valeur [null], qui signifie « pas de valeur ». On parle de type valeur nullable. Le principe vaut pour tous les types valeur : [double?], [bool?], [DateTime?], ...

    Une variable d'un type référence, comme [string], peut depuis toujours valoir [null] : cela signifie qu'elle ne référence aucun objet. Utiliser un membre d'une telle variable, par exemple sa propriété [Length], provoque alors une erreur à l'exécution ([NullReferenceException]), l'une des plus fréquentes en C#. Depuis C# 8, le compilateur peut aider à l'éviter : avec les types référence nullables, activés par défaut dans les projets créés par la commande [dotnet new] et dans les applications fichier unique,

    • le type [string] désigne une chaîne qui ne vaut jamais [null] ;
    • le type [string?] désigne une chaîne qui peut valoir [null].

    Le compilateur suit les valeurs possibles des variables et émet un avertissement lorsqu'on risque d'utiliser une valeur [null] : affectation de [null] à une variable [string], utilisation de [Length] sur une variable [string?] qui n'a pas été testée, etc. Contrairement à [int?], [string?] ne crée pas un nouveau type à l'exécution : c'est une indication destinée au compilateur.

    3.3.6. Les tableaux de données

    Un tableau C# est un objet permettant de rassembler sous un même identificateur des données de même type. Sa déclaration est la suivante :

    1
    Type[] tableau = new Type[n];

    [n] est le nombre de données que peut contenir le tableau. La syntaxe [tableau[i]] désigne la donnée n° i, où i appartient à l'intervalle [0, n-1]. Toute référence à la donnée [tableau[i]] où i n'appartient pas à l'intervalle [0, n-1] provoque une exception. À sa création, chaque élément du tableau reçoit la valeur par défaut de son type : 0 pour les nombres, [false] pour les booléens, [null] pour les types référence. Un tableau peut être initialisé en même temps que déclaré :

    1
    int[] entiers = new int[] { 0, 10, 20, 30 };

    ou plus simplement :

    1
    int[] entiers = { 0, 10, 20, 30 };

    ou encore, depuis C# 12, avec une expression de collection :

    1
    int[] entiers = [0, 10, 20, 30];

    C'est cette dernière forme que nous utiliserons désormais. Les tableaux ont une propriété [Length] qui est leur nombre d'éléments.

    Un tableau à deux dimensions est déclaré comme suit :

    1
    Type[,] tableau = new Type[n, m];

    où [n] est le nombre de lignes et [m] le nombre de colonnes. La syntaxe [tableau[i, j]] désigne l'élément j de la ligne i. Le tableau à deux dimensions peut lui aussi être initialisé en même temps qu'il est déclaré :

    1
    double[,] reels = { { 0.5, 1.7 }, { 8.4, -6 } };

    3.4.1. Écriture sur écran

    Il existe différentes instructions d'écriture à l'écran :

    1
2
3
    Console.Out.WriteLine(expression);
Console.WriteLine(expression);
Console.Error.WriteLine(expression);

    où [expression] est toute donnée qui puisse être convertie en chaîne de caractères pour être affichée à l'écran. Tous les objets de C# ou .NET ont une méthode [ToString()] qui est utilisée pour faire cette conversion. La méthode [Write] fait la même chose que [WriteLine] sans passer à la ligne.

    La classe [System.Console] donne accès aux opérations d'écriture à l'écran ([Write], [WriteLine]). Elle a deux propriétés [Out] et [Error] qui sont des flux d'écriture de type [TextWriter] :

    • [Console.WriteLine()] est équivalent à [Console.Out.WriteLine()] et écrit sur le flux [Out], associé habituellement à l'écran ;
    • [Console.Error.WriteLine()] écrit sur le flux [Error], habituellement associé lui aussi à l'écran.

    Les flux [Out] et [Error] peuvent être redirigés vers des fichiers au moment de l'exécution du programme, comme nous le verrons prochainement.

    3.4.2. Lecture de données tapées au clavier

    Le flux de données provenant du clavier est désigné par l'objet [Console.In] de type [TextReader]. Ce type d'objet permet de lire une ligne de texte avec la méthode [ReadLine] :

    1

    La classe [Console] offre une méthode [ReadLine] associée par défaut au flux [In]. On peut donc écrire :

    1
    string? ligne = Console.ReadLine();

    La ligne tapée au clavier, sans la marque de fin de ligne, est rangée dans la variable [ligne] et peut ensuite être exploitée par le programme. Comme nous l'avons vu, [ReadLine] rend [null] lorsque le flux d'entrée est épuisé : c'est pourquoi la variable est de type [string?]. Le flux [In] peut être redirigé vers un fichier, comme les flux [Out] et [Error].

    3.4.4. Redirection des entrées-sorties

    Windows, Linux et macOS connaissent trois périphériques standard :

    • le périphérique d'entrée standard, qui désigne par défaut le clavier et porte le n° 0 ;
    • le périphérique de sortie standard, qui désigne par défaut l'écran et porte le n° 1 ;
    • le périphérique d'erreur standard, qui désigne par défaut l'écran et porte le n° 2.

    En C#, le flux d'écriture [Console.Out] écrit sur le périphérique 1, le flux d'écriture [Console.Error] écrit sur le périphérique 2 et le flux de lecture [Console.In] lit les données provenant du périphérique 0.

    3.4.5. Affectation de la valeur d'une expression à une variable

    On s'intéresse ici à l'opération [variable = expression;]. L'expression peut être de type arithmétique, relationnelle, booléenne, caractères, etc.

    3.4.5.1. Interprétation de l'opération d'affectation

    L'opération [variable = expression;] est elle-même une expression dont l'évaluation se déroule de la façon suivante :

    • la partie droite de l'affectation est évaluée : le résultat est une valeur V ;
    • la valeur V est affectée à la variable ;
    • la valeur V est aussi la valeur de l'affectation, vue cette fois en tant qu'expression.

    C'est ainsi que l'opération [V1 = V2 = expression] est légale. L'opérateur = étant évalué de droite à gauche, on a [V1 = (V2 = expression)]. L'expression [V2 = expression] est évaluée et a pour valeur V. Son évaluation a provoqué l'affectation de V à V2. L'opérateur = suivant est alors évalué sous la forme [V1 = V]. La valeur de cette expression est encore V ; son évaluation provoque l'affectation de V à V1. Ainsi donc, l'opération [V1 = V2 = expression] est une expression dont l'évaluation :

    • provoque l'affectation de la valeur de [expression] aux variables V1 et V2 ;
    • rend comme résultat la valeur de [expression].

    On peut généraliser à une expression du type [V1 = V2 = ... = Vn = expression].

    3.4.5.3. Priorités dans l'évaluation des expressions arithmétiques

    La priorité des opérateurs lors de l'évaluation d'une expression arithmétique est la suivante (du plus prioritaire au moins prioritaire) :

    1

    3.4.5.4. Expressions relationnelles

    Les opérateurs sont les suivants : <, <=, ==, !=, >, >=. Leurs priorités :

    • >, >=, <, <= ;
    • ==, !=.

    Le résultat d'une expression relationnelle est le booléen [false] si l'expression est fausse, [true] sinon.

    Comparaison de deux caractères

    Soient deux caractères C1 et C2. Il est possible de les comparer avec les opérateurs <, <=, ==, !=, >, >=. Ce sont alors leurs codes Unicode, qui sont des nombres, qui sont comparés. Selon l'ordre Unicode, on a les relations suivantes :

    1
    espace < .. < '0' < '1' < .. < '9' < .. < 'A' < 'B' < .. < 'Z' < .. < 'a' < 'b' < .. < 'z' < .. < 'é'

    Comparaison de deux chaînes de caractères

    Elles sont comparées caractère par caractère. La première inégalité rencontrée entre deux caractères induit une inégalité de même sens sur les chaînes. Soit à comparer les chaînes "Chat" et "Chien" :

    1
2
3
4
5
    "Chat"    "Chien"
---------------------
'C'   =   'C'
'h'   =   'h'
'a'   <   'i'

    Cette dernière inégalité permet de dire que "Chat" < "Chien". Soit à comparer les chaînes "Chat" et "Chaton". Il y a égalité jusqu'à épuisement de la chaîne "Chat". Dans ce cas, la chaîne épuisée est déclarée la plus « petite ». On a donc la relation "Chat" < "Chaton".

    Fonctions de comparaison de deux chaînes

    On peut utiliser les opérateurs relationnels == et != pour tester l'égalité ou non de deux chaînes, ou bien la méthode [Equals] de la classe [System.String]. Pour les relations < <= > >=, les opérateurs ne s'appliquent pas aux chaînes : il faut utiliser la méthode [CompareTo] de la classe [System.String] ou la méthode statique [string.Compare]. Elles rendent un entier :

    • nul si les deux chaînes sont égales ;
    • positif si la chaîne n° 1 est supérieure à la chaîne n° 2 ;
    • négatif si la chaîne n° 1 est inférieure à la chaîne n° 2.

    Il y a une subtilité : [CompareTo] et [string.Compare] ne comparent pas simplement les codes Unicode. Ils suivent les règles de tri de la culture courante, celles d'un dictionnaire : en français, "élan" se range avant "face", bien que le code de 'é' (233) soit supérieur à celui de 'f' (102). Pour choisir le mode de comparaison, [string.Compare] et [Equals] acceptent un paramètre de type [StringComparison] :

    • [StringComparison.Ordinal] : comparaison des codes Unicode, caractère par caractère. C'est la comparaison la plus rapide, à utiliser pour les identifiants, les mots clés, les noms de fichiers ;
    • [StringComparison.OrdinalIgnoreCase] : idem, sans tenir compte de la différence entre majuscules et minuscules ;
    • [StringComparison.CurrentCulture] (le défaut de [CompareTo]) : selon les règles de la culture courante, pour trier des textes destinés à l'utilisateur.

    L'opérateur == et la méthode [Equals] sans paramètre font une comparaison ordinale.

    3.4.5.5. Expressions booléennes

    Les opérateurs utilisables sont ET (&&), OU (||) et NON (!). Le résultat d'une expression booléenne est un booléen. Priorités des opérateurs :

    • ! ;
    • && ;
    • ||.
    1
2
    double x = 3.5;
bool valide = x > 2 && x < 4;

    Les opérateurs relationnels ont priorité sur les opérateurs && et ||. Ces deux opérateurs n'évaluent leur opérande droit que si c'est nécessaire : dans [a && b], b n'est pas évalué si a est faux ; dans [a || b], b n'est pas évalué si a est vrai. On dit qu'ils sont « court-circuités ». On peut ainsi écrire sans risque [texte != null && texte.Length > 0].

    3.4.5.7. Combinaison d'opérateurs

    [a = a + b] peut s'écrire [a += b] ; [a = a - b] peut s'écrire [a -= b]. Il en est de même avec les opérateurs /, %, *, <<, >>, >>>, &, |, ^. Ainsi [a = a / 2;] peut s'écrire [a /= 2;].

    3.4.5.8. Opérateurs d'incrémentation et de décrémentation

    La notation [variable++] signifie [variable = variable + 1] ou encore [variable += 1]. La notation [variable--] signifie [variable = variable - 1] ou encore [variable -= 1]. Utilisés dans une expression, ces opérateurs ont deux formes :

    • [i++] (postfixée) : la valeur de l'expression est la valeur de i avant l'incrémentation ;
    • [++i] (préfixée) : la valeur de l'expression est la valeur de i après l'incrémentation.

    3.4.5.9. L'opérateur ternaire ?

    L'expression [expr_cond ? expr1 : expr2] est évaluée de la façon suivante :

    • l'expression [expr_cond] est évaluée. C'est une expression booléenne ;
    • si elle est vraie, la valeur de l'expression est celle de [expr1], et [expr2] n'est pas évaluée ;
    • si elle est fausse, c'est l'inverse qui se produit : la valeur de l'expression est celle de [expr2], et [expr1] n'est pas évaluée.

    L'opération [i = (j > 4 ? j + 1 : j - 1);] affectera à la variable i : j+1 si j>4, j-1 sinon. C'est la même chose que d'écrire [if (j > 4) i = j + 1; else i = j - 1;], mais c'est plus concis.

    3.4.5.10. Les opérateurs ??, ??= et ?.

    3.4.5.12. Les changements de type

    Il est possible, dans une expression, de changer momentanément le codage d'une valeur. On appelle cela changer le type d'une donnée, ou en anglais « type casting ». La syntaxe du changement du type d'une valeur dans une expression est la suivante :

    1
    (type) valeur

    La valeur prend alors le type indiqué. Cela entraîne un changement de codage de la valeur. On distingue :

    • les conversions implicites, faites automatiquement par le compilateur lorsqu'elles ne font pas perdre d'information : d'un [int] vers un [long], d'un [int] vers un [double], d'un [char] vers un [int], etc. La conversion d'un [long] vers un [double] est elle aussi implicite, bien qu'elle puisse perdre en précision au-delà de 2⁵³ ;
    • les conversions explicites, qui peuvent perdre de l'information et que le programmeur doit demander avec la notation (type) : d'un [double] vers un [int] (la partie décimale est perdue), d'un [long] vers un [int] (les bits de poids fort sont perdus), etc.

Le mot clé [checked] demande au contraire qu'un dépassement lance une exception [OverflowException]. Il s'applique à une expression, [checked(expression)], ou à un bloc d'instructions, [checked { ... }].

    3.5.1. Arrêt

    La méthode [Exit] de la classe [Environment] permet d'arrêter l'exécution d'un programme :

    1

    3.9. Les énumérations

    Une énumération est un type de données dont le domaine de valeurs est un ensemble de constantes entières nommées. Considérons un programme qui a à gérer des mentions à un examen. Il y en aurait cinq : Passable, AssezBien, Bien, TresBien, Excellent. On peut alors définir une énumération pour ces cinq constantes :

    1
    enum Mentions { Passable, AssezBien, Bien, TresBien, Excellent }

    De façon interne, ces cinq constantes sont codées par des entiers consécutifs commençant par 0 pour la première constante, 1 pour la suivante, etc. On peut aussi fixer ces valeurs : [enum Mentions { Passable = 10, AssezBien = 12, ... }]. Une variable peut être déclarée comme prenant ses valeurs dans l'énumération :

    1
    Mentions maMention = Mentions.Passable;

    On peut comparer une variable aux différentes valeurs possibles de l'énumération :

    1

{

}

    • [Enum.GetValues<Mentions>()] (.NET 5) rend le tableau des valeurs de l'énumération [Mentions] ;
    • [Enum.GetNames<Mentions>()] rend le tableau de leurs noms ;
    • [Enum.TryParse(chaine, out Mentions m)] convertit une chaîne en valeur de l'énumération.

    3.10. Passage de paramètres à une fonction

    Nous nous intéressons ici au mode de passage des paramètres d'une fonction. Considérons la fonction suivante :

    1
2
3
4
5
    static void ChangeInt(int a)
{
    a = 30;
    Console.WriteLine($"Paramètre formel a={a}");
}

    Dans la définition de la fonction, ligne 1, [a] est appelé un paramètre formel. Il n'est là que pour les besoins de la définition de la fonction [ChangeInt]. Il aurait tout aussi bien pu s'appeler [b]. Considérons maintenant une utilisation de cette fonction :

    1
2
3
    int age = 20;
ChangeInt(age);
Console.WriteLine($"Paramètre effectif age={age}");

    Ici, dans l'instruction de la ligne 2, [age] est le paramètre effectif qui va transmettre sa valeur au paramètre formel [a]. Nous nous intéressons à la façon dont un paramètre formel récupère la valeur d'un paramètre effectif.

    3.10.1. Les modes de passage

    C# propose les modes de passage suivants :

    • par valeur (le mode par défaut) : la valeur du paramètre effectif est recopiée dans le paramètre formel correspondant. On a deux entités distinctes : si la fonction modifie le paramètre formel, le paramètre effectif n'est en rien modifié. Ce mode convient aux paramètres d'entrée d'une fonction ;
    • par référence avec [ref] : le paramètre effectif et le paramètre formel sont une seule et même entité. Si la fonction modifie le paramètre formel, le paramètre effectif est lui aussi modifié. Le mot clé [ref] doit figurer à la fois dans la définition de la fonction et dans l'appel. Le paramètre effectif doit avoir une valeur avant l'appel. Ce mode convient aux paramètres d'entrée-sortie ;
    • par référence avec [out] : comme [ref], mais le paramètre est uniquement un paramètre de sortie : le paramètre effectif n'a pas besoin de valeur initiale, et la fonction doit affecter une valeur au paramètre formel. C'est le mode utilisé par les méthodes [TryParse]. Depuis C# 7, la variable peut être déclarée dans l'appel : [out var x] ou [out int x] ;
    • par référence en lecture seule avec [in] (C# 7.2) : le paramètre est passé par référence, ce qui évite la copie, mais la fonction ne peut pas le modifier. Ce mode n'a d'intérêt que pour des structures volumineuses ; pour les types prédéfinis, le passage par valeur est aussi efficace.

    3.10.2. Paramètres optionnels, arguments nommés, nombre variable de paramètres

    C# 4 a ajouté les paramètres optionnels : un paramètre peut recevoir une valeur par défaut dans la définition de la fonction ; l'appelant peut alors l'omettre. Les paramètres optionnels se placent après les paramètres obligatoires. Il a ajouté aussi les arguments nommés : à l'appel, on peut faire précéder un paramètre effectif du nom du paramètre formel suivi de deux-points. On peut alors omettre un paramètre optionnel qui en précède d'autres, ou donner les paramètres dans un ordre quelconque.

Depuis C# 13, le paramètre [params] peut aussi être d'un autre type de collection, comme [List<T>] ou [ReadOnlySpan<T>].

    3.11. Les fonctions locales et les tuples

    3.11.1. Les fonctions locales

    Une fonction locale (C# 7) est une fonction définie à l'intérieur d'une méthode, ou, comme dans nos exemples, parmi les instructions de haut niveau. Elle n'est utilisable qu'à cet endroit. Puisque nos programmes n'ont plus de classe, les fonctions locales y remplacent les méthodes statiques des exemples de 2008. Une fonction locale :

    • peut être appelée avant sa définition ;
    • peut utiliser les variables locales qui l'entourent, sauf si elle est déclarée [static] : le mot clé [static] (C# 8) garantit qu'elle ne dépend que de ses paramètres, ce qui la rend plus facile à comprendre. Nous déclarons nos fonctions locales [static] chaque fois que c'est possible ;
    • peut avoir un corps d'expression : [static int Carre(int x) => x * x;] est équivalent à un corps [{ return x * x; }].

    Dans un programme plus important, on écrit des classes et des méthodes : c'est l'objet du chapitre suivant.

    3.11.2. Les tuples

    Un tuple (C# 7) regroupe plusieurs valeurs, éventuellement de types différents, en une seule. Le type [(int, string)] désigne un couple formé d'un entier et d'une chaîne ; ses éléments s'appellent [Item1] et [Item2]. On peut les nommer : [(int Numero, string Nom)]. Un tuple peut être déconstruit : [var (numero, nom) = t;] range ses éléments dans deux variables.

    Les tuples permettent à une fonction de rendre plusieurs valeurs sans utiliser de paramètres [out] : c'est souvent plus lisible.

{

    foreach (int v in valeurs)
    {
        if (v < min) min = v;
        if (v > max) max = v;
    }
    return (min, max);
}
